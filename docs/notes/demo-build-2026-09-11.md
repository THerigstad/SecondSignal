# The demonstration page: how it was built, and what its acceptance run measured

*A build record, 11 September 2026. The page is `demo/index.html`; the builder was OpenAI Codex (GPT-6, default collaboration mode; the exact variant and reasoning setting were not exposed to the builder and are not guessed); the design was ChatGPT-6 Astra's; the orders were the Primary Design Agent's; the operator handed each zip over and ruled on the plates. Nothing here was typed into the page: every figure below was measured by the builder's acceptance run in a real Chromium (version 152.0.4191.66, through Playwright, fetching the interpreter from the pinned address) on the tree at commit af5d8d2 with this push's changes applied, and the page recomputes all of them in every visitor's browser.*

## Two rounds

**Round 1 (10 September).** One order to two builders in parallel, and one design brief to a designer, none seeing the others: Grok Build and Codex each returned a working page; Astra returned five mockups, a one-page style sheet with measured contrast pairs, and notes. Both pages booted the real package, verified every file by hash, ran the labelled cases and the three review sets, and shut their own network off. The builders caught two defects in the order, both by Codex and neither by Grok: the workflow permission it specified (`id-token: read`) would have made the deploy step fail, and its names rule was unsatisfiable as written, because content the library emits (a fixture's retired alias, the resource rows' country and service names, the reviewer labels) carries names. Codex marked that acceptance item as failed with the reason rather than passing it; that honesty is the reason its page became the base for round 2. Both defects are on the failures ledger (`docs/confessions.md`).

**Round 2 (11 September).** One order to Codex: integrate Astra's design into its own page, apply the workflow correction and the corrected names rule (what the builder types versus what the library emits), and carry the operator's ruling of the same night on the plates (ADR-0026 (Proposed), amendment 1): two name forms on every seat, the full form first and the shortened second, printed twice when the name does not shorten, each with its label; a presentation setting with four answers that changes what the plates show and how the seat is named and never the decision; the neutral presentation's name as the visitor's pick. The library changes that carry the ruling (the presentation block, `AgentProfile.plate`, `AgentProfile.name_for`, `tests/test_presentations.py`) were made and tested by the design agent first and supplied to the builder, so the page reads every name from the library. The first return stopped at a gate the order had written from one host's test count (the order gave 1,104 passing with one skip; the builder's host built the wheel and measured 1,105) and returned a log that built nothing and faked nothing; the order was corrected to name both outcomes and the builder continued. That gate is the third ledger entry from this build (the assistant's, all three).

## What the acceptance run measured (all sixteen items passed; 215 assertions, none failing)

- Boot: the header shows the commit, 57 files verified against the manifest (every entry logged as verified, none rejected), Python 3.14.2, library version 0.2.0.
- The fourteen examples: every expected field (seat, assist, outcome, safety action, crisis read, card, latch, holds, integrity event, number of attached lines) equal to the labelled expectation, prior turns replayed through the same session where the case has them.
- The labelled-case suite in the browser: exit 0, `226 passed, 193 xfailed in 4.65s`, the expected failures grouped by the reason prefix pytest printed.
- The three external review sets: round1-2026-09-02, 103 (79 pass as written, 13 contract-adjusted, 10 disputed, 1 known gap); acceptance-2026-09-03, 26 (18, 0, 3, 5); round2-2026-09-08, 36 (30, 4, 1, 1); all 38 non-passing cases opened with a non-empty note; all 165 cases reachable.
- Network: after boot, every one of the five entry points throws; the whole-session request log holds only the site's own files and the pinned interpreter's.
- The plates: all seven name-and-label pairs equal to `profile.plate` from the roster, in order, the four names that do not shorten printed twice.
- The setting never reaches the library: on the grief example, the decision record and the trace are byte-identical under women, men, neither and as written, while the seat sentence reads Willow (she), Will (he), Willow (they), Willow (she).
- Neither: the second form on the seated plate is selectable by keyboard, the seat sentence becomes Will (they), the record and trace do not change, and leaving the setting clears the pick.
- The operator's sentence appears once, above the table.
- 400 pixels wide: no horizontal overflow; the examples closed behind a disclosure with the content note visible; a jump link after each decision that focuses the table without moving the transcript; every plate readable in full.
- Contrast: every text role measured against its computed background; the lowest pair 5.25:1 (charcoal on sage, an eligible plate's name), above the 4.5:1 line.
- The whole suite on the tree: 1,106 passed and 193 expected failures on the builder's host, where the packaging check runs; 1,105 with that check skipped as a machine fault on the design agent's three fresh environments (Python 3.10, 3.11, 3.12); `ruff` and `mypy` clean.

## What is not claimed

The acceptance run was the builder's, on the builder's machine, before the page was published; the published page is checked in the operator's own browser after the Pages switch, and the README links to it only after that check. The page runs the policy layer only: no language model runs on it, none of the characters speak, and the crisis card's lines are the library's, shown as the library returns them. The full build logs (with the complete console record, the request log and the fourteen comparisons verbatim) are in the operator's archive, not committed, because they run to hundreds of kilobytes of tool output; the figures above are copied from them without change.
